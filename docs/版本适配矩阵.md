# 版本适配矩阵

本文件记录**每个实测过的 Claude Code 版本**，以及当时的适配结论与验收数据。
新增版本请追加一行，并在 `data/versions.json` 同步登记（`status` 决定扩展是否弹"未测试版本"确认框）。

状态含义：

| status | 含义 |
|---|---|
| `verified` | 已在本机实测：应用 → 断言 → 还原 → 断言 → 再应用 全通过（`tools/selftest.js`） |
| `untested` | 未实测。按通用规则尽力适配；未覆盖的新文案保持英文，`tools/audit.js` 可列出 |
| `broken` | 已知不兼容，**禁止应用** |

## 覆盖率口径

`node tools/audit.js` 的统计口径（以 2.1.329 为例）：

```
【webview】候选 3715 · 已汉化 1785 (48.0%) · 登记跳过 98 · 范围外 1290
   ✓ 无遗留 Claude 界面文案
【host】   候选 965  · 已汉化 434  (45.0%) · 登记跳过 16 · 范围外 77
   ✓ 无遗留 Claude 界面文案
```

- **候选**：经"界面位置识别"判定为展示文本的字面量种数
- **已汉化**：命中词条并已替换
- **登记跳过**：`data/i18n-skip.json` 逐条登记原因（按键名、协议标签、内部标识…）
- **范围外**：`data/i18n-outofscope.json` 逐类登记原因（内嵌 Monaco/VS Code 编辑器、KaTeX、
  JSON-Schema 文档、发送给模型的提示词、URL 与模型 ID…）
- **判定门槛**：`遗留 Claude 界面文案 = 0` 才算通过。

> 分母里包含大量内嵌 Monaco 编辑器与第三方组件的字符串，所以"已汉化 48%"并不等于
> "界面还有一半英文"。真正的门槛是最后那行：**没有任何一条仍属于 Claude 界面的文案是英文**。

## 适配新版本的最小步骤

```bash
node tools/cli.js reset     # 丢弃旧快照（新版本目录已变）
node tools/audit.js         # 看「仍属 Claude 界面但未翻译」清单
#   把清单条目补进 data/i18n-<版本>.json（只写文案本身，${...} 原样保留）
node tools/build.js         # 重建词典
node tools/selftest.js      # 11 项断言
#   在 data/versions.json 与本文件登记新版本
```
