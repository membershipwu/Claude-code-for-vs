# 技术说明

本文说明汉化规则、安全边界和可重放的本机测试。版本覆盖数据以版本适配矩阵为准。

## 改写流程

1. 读取已安装的 Claude Code 版本，并加载单独保存在 VS Code globalStorage 的英文基线。
2. 用手写词法器识别目标 JavaScript bundle 的字符串、模板字符串和代码 token。
3. 用界面属性、枚举状态和受限 VS Code 消息 API 锚点识别可翻译字面量。
4. 排除比较表达式、case、成员名、对象键、属性键、协议及名称位置。
5. 计算所有译文，验证源码 token 数量、类型和未修改项，再检查 JavaScript 语法。
6. 分批暂存所有文件；如果替换其中一个文件失败，则尽可能把已替换文件回退。

manifest 与演练文件是独立的结构化文件，JSON 先完整解析后再修改。改写器不会复制或打包 Anthropic 的 bundle。

## 为什么需要词法器

对 minified JavaScript 做全局字符串替换会连带改写协议值、对象名和导出名；字符串、正则表达式与嵌套模板语法也不能可靠地用一个简单正则区分。lib/lexer.js 对 token 区间分类，planner 只返回有 UI 锚点的替换候选。

翻译候选仍须满足原 token 的结构边界。重新词法扫描后，只能有预先规划的字面量值变化；新旧源码都必须可解析。

## 宿主翻译范围

Claude Code 2.1.329 的扩展宿主包含动态生成校验代码的 schema。历史宽范围翻译后的运行记录出现过 SyntaxError；具体坏掉的替换仍未查清。data/scope.json 因此将宿主侧限制在 api 类锚点。该限制保留常用用户可见的宿主通知及选择框翻译，并避免扩大到 schema 和任意内部文案。

webview 与宿主共用 planner，但分别使用范围配置。tools/audit.js 与 tools/gap.js 也读取相同的 scope；旧版不应用该限制的宿主覆盖率数字不代表当前构建。

这只能说明已检查范围内的代码自证与记录中的实际运行，不能证明所有扩展版本或所有屏幕均没有问题。详见版本适配矩阵。

## 快照、恢复与写入

- 快照按 Claude Code 版本分目录存储；清单记录目标文件及 SHA-256。
- 读取基线会检查版本、必要条目、目标文件名与每个文件的校验和。任何不匹配都会中止改写或恢复。
- 每批目标先完整写入同目录的临时文件，再依序替换。文件系统错误时，将已替换文件恢复到本次运行前读取的字节。
- 整个系统不能保证断电或强制结束进程期间多个独立文件的全局事务性；发现残留临时文件或中断后，请先检查 VS Code 日志并使用经校验的英文快照还原。
- 仓库、npm 构建产物和 VSIX 不包含英文基线。基线属于用户本地数据。

## 回归测试

~~~sh
npm run verify
node tools/selftest.js
~~~

tools/test.js 使用 Node.js 内置测试框架，检查三个状态栏目、快照摘要及路径防护、目标文件逐字节恢复、故障注入时的写入回退，以及宿主 schema 边界。tools/extension-smoke.js 使用隔离的扩展目录和 VS Code API 桩件，实际调用扩展命令中的汉化与恢复流程。

tools/selftest.js 将指定的 Claude Code 扩展文件与可信基线复制至临时目录，完成 11 项 apply、restore 和幂等断言。它不会改写已安装扩展，不会调用真实 Claude 会话，也不等同于启动完整的 Claude Code VS Code 宿主。

## 真实激活故障

2026-11-20 的历史日志记录一次宿主宽范围翻译后的 Zod 编译语法错误；具体条目没有完成单条归因。后续收紧宿主范围后，VS Code 扩展宿主日志记录了 Anthropic Claude Code 扩展成功激活并初始化 webview。这个证据不代表全量范围已修复，也不是当前版本所有界面的视觉验收。

如再次遇到面板无法打开，先在输出目录检查 Claude VSCode 通道和 VS Code 扩展宿主日志中的激活异常。排查后重试时，优先使用隔离副本；不要为了提高统计覆盖率直接扩大 host 范围。问题模板中不要包含凭据、用户目录、会话内容或项目路径。
